# LossBalance-v2 Experiment Log

## Purpose

LossBalance-v1 removes pixel-area dominance by averaging reconstruction error
inside each sample/organ pair. It does not remove sample-frequency dominance:
an organ that occurs in few training slices/windows still contributes on fewer
optimizer steps.

LossBalance-v2 changes only the ROI loss. It does not change the dataset order,
sampler, OWT architecture, token masking policy, global L2, or LPIPS term.

## Objective

For foreground class `c`, let `N_c` be the number of training samples/windows
that contain the class and let `N` be the dataset size. The unnormalized class
weight is

```text
r_c = N_c^(-alpha)
```

The foreground weight ratio is capped, then all weights are scaled so that
their expected total mass per uniformly sampled input is one:

```text
sum_c (N_c / N) * w_c = 1
```

The minibatch ROI loss is

```text
L_roi_v2 = (1 / B) * sum_b sum_{c present in b} w_c * e_{b,c}
```

where `e_{b,c}` is first averaged over pixels and channels inside one
sample/organ pair. Background has weight zero. Division by fixed batch size is
intentional: renormalizing by the classes present in the current batch would
undo part of the rare-class correction.

The first controlled setting is `alpha=0.5`, maximum weight ratio `4.0`, and
`lambda_roi=1.0`. `alpha=1` is exact inverse positive-sample frequency; the
square-root setting is chosen first to reduce optimization shock.

## Isolation and compatibility

- Branch: `experiment/lossbalance-v2`
- Worktree: `/gpfs/work/aac/bolinren19/OD_OWT_lossbalance_v2`
- Base commit: clean `main` commit `6cdf9b5`
- Original OWT entry points are unchanged.
- `roi_class_weights` is a non-persistent model buffer, so v2 has no new
  trainable parameters and its state-dict keys/shapes match original OWT.
- The loader contains only the established `fixed_255` normalization control
  needed to match LossBalance-v1; CropMix is not included.

## Local validation

- 5 loss tests pass: exact inverse-frequency weights, expected-mass
  normalization, ratio cap, invalid inputs, 2D/3D loss and gradients.
- Original OWT and v2 state-dict keys/shapes match.
- 2D forward/backward passes with finite loss and gradients.
- Fixfr4 3D forward/backward passes with finite loss and gradients.
- A 20-step one-sample tiny overfit reduces loss by at least 20%.
- Both full and smoke Slurm scripts pass `bash -n`.

## Controlled training configuration

The comparison keeps the v1 settings: WORD Common8, 224 input, 20 tokens per
class, mask ratio range controlled by `--mask_ratio 1.0`, global L2 + ROI-L2 +
LPIPS, base LR `1e-4`, effective global batch 64, and 1200 epochs.

- 2D: 2 GPUs x batch 32.
- Fixfr4 3D: 4 GPUs x batch 16. This follows the four-GPU policy while keeping
  the same global batch and automatic LR as the earlier 2-GPU x 32 run.

## Staged launch policy

1. Submit one-epoch 2D and Fixfr4 3D smoke jobs.
2. Check finite loss, all class diagnostics, peak GPU memory, throughput,
   checkpoint creation, and absence of traceback/OOM.
3. Only after both pass, submit the two 1200-epoch jobs.
4. Submit the same Direct and LoRA evaluation used for the controlled baseline,
   dependent on successful full training.
